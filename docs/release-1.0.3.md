# FinderWrap 1.0.3 · 分组识别兼容修复

2026-10-26 正式发布，build 6。[GitHub Release](https://github.com/ygnstudio/FinderWrap/releases/tag/v1.0.3) 和 Homebrew 已更新，安装包采用提交 `5a4ee23` 的固定签名 CI 产物。macOS 15.7.4 / 15.8.1 反馈机的实际效果仍待确认。

## 变更

1.0.1 / 15.7.4 用户诊断停在 `section-0`，尚未取得具体 subrole / count / AXError。本次没有把该日志解释成已证实的某一种结构。可独立证明的实现缺陷是：即使已验证图标焦点、窗口归属以及后续有效图标结构，旧逻辑仍将可选 `AXSubrole` 的缺失当作拒绝条件。系统 SDK 的 `AXAttributeConstants.h` 明确该属性不是每个元素都必须提供。

1.0.3 要求分组基本类型为 `AXList`，子类型支持已知 `AXSectionList`、通用 `AXUnknown` 及明确的 attributeUnsupported / noValue。错误类型、明确其他子类型、通信失败、失效元素继续拒绝；每个包装、图标、坐标、选择状态及日期标题都继续完整验证。没有加入任意层级搜索或跳过不认识的节点。

内置诊断现在区分分组角色、子类型、子节点读取、空组、项目包装、数量超限、AX 错误、分页异常和读后数量变化。150 ms 总预算、10 ms 单次 AX 超时、350 ms 缓存、24 组 / 160 项限制及写前单选/几何/焦点、写后读回保护保持原值。已有的大目录限制没有在本版取消。

独立只读分组探针保留为历史 1.0.1/1.0.2 的支持工具，明确标出所模拟的旧版守卫，不进入安装包。1.0.3 用户优先复制应用自身诊断。

## 验证

- 从生产 `capture` 抽取同一布局解析方法，测试通过 AX 边界注入调用真实解析器及导航算法，不复制一套替代算法。
- 隔离副本运行旧守卫，68 项测试出现 14 个失败断言；修复后 68 项 XCTest 全部通过。旧版失败包含可选子类型被拒、基本 role 未核对以及缺失具体拒绝诊断。
- 17 项 Python 测试通过，含 5 项签名策略和 12 项只读探针测试；CI 已接入两类测试和 `.command` 语法检查。
- 隔离源码完成 Apple Silicon / Intel 通用 Release 构建。
- 原生 Synthetic 检查先遇到折叠分组返回失效元素，之后因 Finder 未保持前台而停止；均未写入。展开分组后仍未取得有效前台，背景只读采样也未形成完整布局。此次原生往返未完成，反馈机实测未完成，不把这些退出记为通过。
- architecture / security 与四个独立对抗审查均未发现新增可证实缺陷。审查不代替跨系统验证。

## 分发和升级

已公开的固定签名 CI 附件为 `FinderWrap-1.0.3-b6-fixed-universal.dmg`、ZIP、SHA-256 和签名清单。复用原固定证书、bundle identifier 与 designated requirement，不创建或更换证书，不生成 ad-hoc 安装包。

支持 macOS 15+ 编译目标、Universal 2；没有 Developer ID 或苹果公证。固定身份应保持升级连续性，但具体机器上的授权保留仍需实际验证。从早期 ad-hoc 包迁移可能需要重新授权。不会在本次发布中替换维护者现有安装版。

若仍不生效，请提供 1.0.3 内置诊断；只报告该机的实际效果，不将一次升级当作所有 macOS 15 环境兼容的证明。
